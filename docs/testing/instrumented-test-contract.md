# Instrumented Test Contract

## 目标

统一 `androidTest` 的边界，让可自动化的内容保持确定性，把人工观察和外部截图留给手工 QA。

## 自动化准则

- 只验证可重复的 UI/状态/帧断言。
- 不使用长时间 `Thread.sleep` 作为通过条件。
- 不把标记文件、外部截图、手工拉日志当成自动化通过标准。
- 游戏页这类持续动画页面，必要时用无障碍树轮询或原生宿主断言，避免被 Compose idle 卡住。

## 应该自动化的内容

- 大厅到详情页的导航。
- 详情页到游戏页的启动流程。
- 真实 libretro host 的加载、运行帧、读帧和音频冒烟。
- 关键 UI 语义节点是否出现。

## 应该留给手工 QA 的内容

- 真实设备上的截图外观确认。
- 音频是否“听感正常”。
- 遥控器、手柄、电视机这种环境依赖较强的完整体验确认。

## 验收口径

- `androidTest` 通过不依赖外部人工步骤。
- 失败时能直接定位到代码或宿主行为，不需要猜测。
- 手工 QA 只补自动化不能覆盖的最后一公里。
